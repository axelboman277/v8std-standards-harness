# Карта: действие в коде → стандарт

Проекция 2 из двух. Отвечает на вопрос **«я сейчас делаю вот это — что обязан проверить?»**.
Первая проекция — по объекту метаданных — в [`standards-map.md`](standards-map.md).

Триггер здесь — **действие**, а не роль и не фаза процесса. Работает одинаково у одиночки без
всякого workflow и у команды с формальными фазами. Если у вас фазы есть — в конце файла
таблица примерного соответствия.

## Уровни (tier)

| Уровень | Что означает |
|---|---|
| **always** | Сверка обязательна каждый раз, когда сработал триггер. Пропуск = дефект. |
| **conditional** | Обязательна при наличии подситуации (фильтрация, JOIN, виртуальная таблица и т. п.). |
| **optional** | Для нестандартных решений и при сомнениях в подходе. |

Тексты стандартов — только через MCP: `v8std_get_page("stdNNN")`. Здесь — указатели.

### Подситуация: составной тип в запросе

Тип поля виден только в метаданных, поэтому триггер **не всегда обнаруживается по тексту
запроса** — состав типов проверяется в структуре объекта до написания запроса.

- **Разыменование** составного поля (`Поле.Реквизит`) — читать std654 (там про неявные
  соединения и почему для составных типов это особенно дорого) и применять типизацию через
  `ВЫБОР … ССЫЛКА` + `ВЫРАЗИТЬ`.
- **Равенство с параметром — наоборот, без `ВЫРАЗИТЬ`.** Это не из стандарта, а практика:
  функция над полем отключает индексный поиск, и время выполнения вырастает на порядки.
  Частая ошибка — применить `ВЫРАЗИТЬ` «на всякий случай» ко всем обращениям к составному
  полю, включая условия отбора.
- Наличие физического индекса оценивать с учётом критериев отбора — их поля платформа
  индексирует даже при свойстве «Не индексировать».
- Любые оптимизации запроса подтверждать замером на живой базе, а не рассуждением.

## Ревью чужого или своего кода

| Что ревьюишь | Источник | Что проверять |
|---|---|---|
| Архитектурное решение | «Проектирование решения» + паттерны | Обоснован ли выбор типа объекта, прав, общего модуля — со ссылкой на конкретные ID. Применены ли `patterns:solid` к новым общим модулям. Для документов с проведением — отдельно std450/std603/std633 |
| Код | «Написание кода» | Полный проход по сработавшим триггерам; каждая находка подкреплена ID стандарта или диагностики. Отдельно: `ОбработкаПроведения` не должна явно вызывать `Записать()` для наборов записей (std450) |
| Тесты | «Написание тестов» | std453/454/455/456 + std761 при наличии UI-текстов |
| Регрессия, падение статического анализа | коды диагностик | `v8std_explain_diagnostics([код])` — даёт связку «диагностика → стандарт» |

## Discovery taxonomy

Машинная часть карты: по каким подстрокам ситуация распознаётся и чем её искать в MCP.
Используется на **слое 2** (proactive discovery) — см. [`../SKILL.md`](../SKILL.md).

> **Честная граница:** сегодня taxonomy читает человек или агент — исполняемого потребителя
> в пакете нет. Это структурированная подсказка, а не автоматический детектор. Если вы
> подключите к ней линтер — сообщите, это давно напрашивается.

```yaml
queries:
  "Проведение документа / движения регистров":
    search_queries:
      - "проведение документа движения Записать наборы записей регистров"
      - "ОбработкаПроведения явная запись движений"
      - "регистры активность движений проведение"
    smell_patterns:
      - "ОбработкаПроведения"
      - "ПриПроведении"
      - "ПередПроведением"
      - "Движения.*.Записать("
      - "НаборЗаписей.Записать("
      - "РежимПроведения"
  "Обработчики событий объектов":
    search_queries:
      - "обработчик событий объекта ПередЗаписью ПриЗаписи"
      - "ОбменДанными.Загрузка ПередЗаписью ПриЗаписи проверка"
    smell_patterns:
      - "Процедура ПередЗаписью"
      - "Процедура ПриЗаписи"
      - "ОбменДанными.Загрузка"
  "Запрос к виртуальной таблице":
    search_queries:
      - "виртуальная таблица параметры обращения индекс"
      - "регистр сведения остатки обороты виртуальная таблица"
    smell_patterns:
      - "ИЗ РегистрНакопления."
      - "ИЗ РегистрСведений."
      - ".СрезПоследних("
      - ".Остатки("
      - ".Обороты("
  "Привилегированный режим":
    search_queries:
      - "привилегированный режим безопасность"
```

то есть закрыта только тем, что кто-то помнит про неё.

## Если у вас есть фазы или роли

Ситуации выше группируются под любой процесс. Пример соответствия — так эта карта была
устроена в проекте-источнике, где работали фазовые агенты:

| Фаза / роль | Какие разделы этого файла применимы |
|---|---|
| Проектирование, архитектура | «Проектирование решения» + паттерны |
| Реализация | «Написание кода» |
| Тесты | «Написание тестов» |
| Ревью | «Ревью чужого или своего кода» (выбор подраздела по предмету ревью) |
| Мелкий фикс без отдельных фаз | «Написание кода», только сработавшие триггеры |

Соответствие приведено как пример, а не как требование: у вас может не быть ни фаз, ни ролей —
карта от этого не перестаёт работать.
