# Как поставить это у себя

Инструкция написана так, чтобы её мог выполнить **агент любой модели** в вашем проекте.
Если вы читаете это глазами — она работает и так, просто длиннее необходимого.

Проверок и решений здесь немного, но два из них влияют на всё остальное, поэтому идут
первыми.

---

## Шаг 0. Проверьте, что вам это нужно

Обвязка имеет смысл, если выполнено **всё** перечисленное:

- вы разрабатываете на 1С:Предприятие (BSL);
- к коду или к проектированию метаданных допущен LLM-агент;
- вам важно, чтобы сверка со стандартами разработки была *проверяемой*, а не декларируемой.

Если агент у вас только читает код и ничего не пишет — хватит одной карты без валидатора.
Если вы не на 1С — пакет вам не подойдёт целиком, но **паттерн** может: см. «Перенос идеи
на другой стек» в конце.

---

## Шаг 1. Подключите MCP-сервис стандартов

Это единственная внешняя зависимость. Endpoint публичный, аутентификация не требуется.

**Claude Code** — в `.mcp.json` проекта:
```json
{
  "mcpServers": {
    "v8std": { "type": "http", "url": "https://ai.v8std.ru/mcp" }
  }
}
```

**Codex CLI** — в `~/.codex/config.toml`:
```toml
[mcp_servers.v8std]
url = "https://ai.v8std.ru/mcp"
```

**Другой харнесс** — подключите HTTP MCP по адресу `https://ai.v8std.ru/mcp` штатным для
него способом.

**Проверка (обязательная, не пропускать):**
```
v8std_get_page("std450")
```
Ожидается `found=true`. Если инструмент недоступен — дальше идти бессмысленно: три из
четырёх слоёв опираются на него.

> **Приватность.** Наружу уходят только ваши поисковые запросы и номера стандартов. Код
> сервису не передаётся. Если и это неприемлемо — соберите офлайн-кэш (Шаг 6).

Доступные инструменты: `v8std_search` (поиск по теме), `v8std_get_page` (полный текст по id),
`v8std_get_related` (связанные стандарты и диагностики), `v8std_explain_diagnostics` (по кодам
ACC / BSLLS / v8-code-style), `v8std_explain_snippet` (по фрагменту BSL или SDBL).

## Шаг 2. Разложите файлы

| Файл | Куда |
|---|---|
| `SKILL.md` | Туда, где ваш харнесс ищет скиллы: `.claude/skills/v8std-standards-harness/`, `~/.codex/skills/`, `.agents/skills/`. Если скиллов нет — куда угодно, но тогда обеспечьте чтение вручную (см. Шаг 3) |
| `references/*.md` | Рядом со `SKILL.md`, в подкаталоге `references/` — ссылки внутри относительные |
| `tools/v8std-evidence-validator.mjs` | В каталог скриптов проекта, например `tools/` |
| `tools/v8std-evidence-validator.smoke.mjs` | Туда же |
| `tools/v8std.config.example.json` | Скопировать как `v8std.config.json` в корень проекта и отредактировать (Шаг 4) |

Проверка: `node tools/v8std-evidence-validator.smoke.mjs` — должно быть `19 passed, 0 failed`.
Требуется Node.js 18+, внешних зависимостей нет.

## Шаг 3. Обеспечьте, чтобы агент карту действительно читал

**Это самый пропускаемый шаг, и без него всё остальное бесполезно.** Наличие файла в
репозитории не означает, что агент его прочитал.

Что нужно сделать — по убыванию надёжности:

1. **Хук перед записью кода** (самое надёжное). Если ваш харнесс поддерживает перехват
   вызовов инструментов, поставьте проверку: перед первой записью BSL в сессии в
   транскрипте должно быть чтение карты. Нет чтения — запись блокируется. Мы пришли к
   этому после того, как убедились: инструкция «прочитай перед работой» выполняется не
   всегда, а хук — всегда.
2. **Явная строка в инструкции проекта** (`CLAUDE.md`, `AGENTS.md`, `.cursorrules`):
   «Перед написанием или ревью BSL прочитать `references/situations.md` и применить
   сработавшие триггеры».
3. **Автозагрузка по маске файлов**, если харнесс умеет: подхватывать карту при открытии
   `*.bsl`.

Минимум — пункт 2. Пункт 1 добавьте, когда убедитесь, что пункта 2 не хватает; обычно на
это уходит около недели.

## Шаг 4. Настройте конфиг

`v8std.config.json` в корне проекта (весь файл необязателен — без него профиль `lint`,
любые метки фаз, скан всех `.md`):

```json
{
  "profile": "gate",
  "phases": ["design", "implement", "review"],
  "evidenceGlobs": ["**/v8std-evidence.md"],
  "promoteReport": "final-report.md",
  "sentinelId": "std450"
}
```

| Поле | Что задаёт | Если не задать |
|---|---|---|
| `profile` | `gate` (fail-closed) или `lint` (только формат) | `lint` |
| `phases` | Метки этапов вашего процесса | Принимается любая непустая метка |
| `evidenceGlobs` | Где искать записи | Все `.md` в проверяемом каталоге |
| `promoteReport` | Файл с секцией «discoveries to promote» | `final-report.md` |
| `sentinelId` | Эталонный ID для проверки живости индекса | `id` в записях не сверяется |

**`sentinelId` подберите сейчас, а не потом.** Найдите самый свежий стандарт, который
сегодня отдаёт сервис, и впишите его:
```
v8std_search("последние добавленные стандарты")   → выберите наибольший stdNNN
v8std_get_page("std<NNN>")                         → убедитесь, что found=true
```
Незафиксированный sentinel не детектирует ничего.

## Шаг 5. Включите гейт в CI

Без автоматического запуска четвёртый слой не существует — «ручная команда, которую надо
не забыть» гейтом не является.

**pre-commit** (`.git/hooks/pre-commit`, не забыть `chmod +x`):
```bash
#!/bin/sh
# Гейт только при изменениях BSL — не мешать правкам документации.
if git diff --cached --name-only | grep -qiE '\.(bsl|os)$'; then
  node tools/v8std-evidence-validator.mjs validate-pack . --gate || exit 1
fi
```

**GitHub Actions:**
```yaml
- name: v8std evidence gate
  run: node tools/v8std-evidence-validator.mjs validate-pack . --gate
```

Коды возврата: `0` — чисто, `1` — предупреждения, `2` — блокирующие нарушения.

**Куда агент пишет записи.** По умолчанию — `v8std-evidence.md` в корне рабочей ветки,
секция `## v8std evidence`. Если у вас уже есть артефакты задач (папка на задачу, лог
работы) — укажите их в `evidenceGlobs`, отдельный файл не нужен.

Минимальный носитель:
```markdown
# Журнал задачи

## v8std evidence

[v8std sentinel: id=std450, status=found, phase=implement]
[v8std applied: phase=implement, scope=document-posting, ids_checked=[std450,std603], conclusion=clean]
[v8std discovered: phase=implement, scope=document-posting, query="проведение документа движения", top_ids=[std450,std633], new_ids=[], decision=noted]
```

## Шаг 6. Офлайн-кэш (необязательно)

Нужен, если внешние сервисы недоступны из вашего контура или вы хотите работать без сети.

**Готового кэша в пакете нет намеренно** — тексты стандартов принадлежат правообладателям,
и распространять их мы не вправе. Соберите свой:

1. Возьмите список ID из `references/standards-map.md` (около 90 в связках).
2. Для каждого — `v8std_get_page("stdNNN")`, сохраните в `v8std-cache/std/<NNN>.md`.
3. Сделайте `INDEX.md` с заголовками для поиска по ключевым словам.
4. Кэш **не коммитьте** — добавьте в `.gitignore`.

Порядок использования: сначала MCP (три попытки), при недоступности — кэш, и только потом
`skipped`. При чтении из кэша тип записи остаётся `applied`, добавляется поле
`source=offline_cache` — валидатор незнакомые поля игнорирует.

Границы: кэш покрывает только `stdNNN`. Паттерны (`patterns:*`) и диагностики
(`acc:` / `bslls:` / `v8cs:`) — только онлайн. Кэш — снимок: при расхождении верен сервис.

## Шаг 7. Ревизия карты

Карта — снимок на дату. Без ревизии она устаревает молча: sentinel этого не поймает
(он ловит недоступность и откат индекса, но не то, что индекс ушёл вперёд).

**Назначьте владельца.** Не «команда», а конкретный человек — иначе не сделает никто.

**Раз в квартал, около часа:**
1. По каждой категории `references/standards-map.md` — `v8std_search` по её теме.
2. Новые ID проверить через `v8std_get_page` и решить: в карту / не подходит.
3. Пересмотреть `sentinelId` — появился более свежий стандарт, возьмите его.
4. Обновить `last_reviewed_at` внизу карты.

**Между ревизиями** карту пополняют находки слоя 2: запись `discovered` с
`decision=applied|noted` означает, что стандарт стоит внести. Валидатор в профиле `gate`
потребует зафиксировать такие находки в `promoteReport` — так они не теряются.

## Перенос идеи на другой стек

Если вы не на 1С, содержимое карты вам не подойдёт, но переносимо главное — **паттерн
проверяемого пропуска**:

> Агент обязан оставить машинно-читаемый след того, что проверка выполнена **или**
> осознанно пропущена с указанием причины из закрытого списка. Молчаливый пропуск
> невозможен, потому что его отсутствие видит валидатор.

Что заменить: карту ситуаций — на свою (стиль, безопасность, требования отрасли); список
`reason` — на свой; sentinel — на любой стабильный признак живости вашего источника истины.
Что перенести без изменений: типы записей, обязательные поля, различие профилей `lint`/`gate`,
правило «ноль записей ≠ чисто».
